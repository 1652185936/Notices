## 1. 笔记加密方案（N-16）

### 1.1 密钥架构

```
Android Keystore (硬件级，不可导出)
 └─ 主密钥 master_key (AES-256-GCM, setUserAuthenticationRequired 可选)
      └─ 加密 DEK (数据加密密钥, 随机 256bit)   → 密文存 DataStore
            └─ DEK 加密每篇笔记 contentJson 与附件
```

- 采用 **信封加密**：Keystore 主密钥只封装 DEK，笔记数据用 DEK 加密。
  好处：将来改密码/换验证方式只需重封装 DEK，不必重加密全部笔记。
- 算法：AES-256-GCM，每次加密随机 12 字节 IV，IV 拼接在密文头部。
- 实现：`androidx.security:security-crypto` 的 MasterKey + 自封装 Cipher（EncryptedFile 用于附件）。

### 1.2 验证流程

```
进入加密笔记
→ BiometricPrompt(指纹) ──成功──→ 解封 DEK → 解密渲染
        │失败3次/无指纹
        ▼
   PIN 输入页（6位，PBKDF2-HMAC-SHA256 派生验证，10万次迭代，盐随机）
   连续错5次 → 冷却60s（指数递增）
```

- PIN 哈希存 DataStore；**明确告知用户：忘记 PIN 且指纹失效则加密笔记无法恢复**（设计取舍：不留后门）。
- 解密后的内容仅存在于内存；编辑加密笔记时自动保存走"加密后落库"管线，明文不落盘。
- 加密笔记的 `plainText` 恒为空串（不进搜索索引、列表只显示标题）。
- 截屏：加密笔记编辑页设置 `FLAG_SECURE`。

### 1.3 加密/解密转换

```
开启加密: 读明文 → DEK加密contentJson → 附件移入 secure/ 并 EncryptedFile 重写
          → isEncrypted=true, plainText="" → 删除明文残留
关闭加密: 逆过程；要求先通过验证
```
转换在前台进行（带进度），事务式：任一步失败全部回滚，绝不留半加密状态。

## 2. 应用锁（S-07, P2）

- 独立于单篇加密：App 进前台超过设定时间（立即/1分钟/5分钟）要求指纹/PIN。
- 仅是访问门禁，不改变数据加密状态；最近任务卡片设 `setRecentsScreenshotEnabled(false)`。

## 3. 提醒可靠性（T-02 关键工程问题）

国产 ROM（含 HarmonyOS 4）对后台/闹钟限制激进，必须多层保障：

| 层 | 措施 |
|----|------|
| 1 | `AlarmManager.setExactAndAllowWhileIdle` + `SCHEDULE_EXACT_ALARM` 权限引导 |
| 2 | `RECEIVE_BOOT_COMPLETED` + 时间/时区变更广播 → rescheduleAll() |
| 3 | App 每次进前台校验：DB 中 active 提醒 vs 已注册闹钟，差异补注册 |
| 4 | 错过的提醒（triggerAt < now 且未触发）→ 立即补发通知并标注"已错过" |
| 5 | 首次设提醒时引导页：指导用户在系统设置中允许自启动/关闭电池优化（华为 ROM 必需） |

通知渠道：`todo_reminder`（IMPORTANCE_HIGH，声音+振动）/ `general`（静默）。

## 4. 性能预算与监控

| 指标 | 预算 | 手段 |
|------|------|------|
| 冷启动 → 列表可交互 | ≤1.5s | App Startup 精简、首屏查询投影列、baseline profile(可选) |
| 列表滚动 | 60fps | LazyGrid + 投影 POJO + Coil 采样 |
| 编辑输入延迟 | ≤50ms | 焦点块局部重组（文档03 §7） |
| 保存耗时 | 不阻塞 UI | 全部 IO/序列化下沉协程 |
| 内存 | 峰值 ≤256MB | 图片采样、查看器单图加载 |
| APK 体积 | ≤25MB | R8 + 资源收缩；ML Kit 用动态下载模型 |

Debug 构建接入 LeakCanary 与 Compose 重组计数检查；Release 不接任何统计 SDK（隐私原则）。

## 5. 备份格式规范（S-02）

### 5.1 包结构（zip）

```
notices-backup-20260610-1930.zip
 ├─ manifest.json      // {formatVersion:1, appVersion, createdAt, counts, encrypted:bool}
 ├─ data.json          // 全量结构化导出：folders/notes/tags/todos/reminders 数组
 └─ attachments/       // 原样目录树 attachments/{noteId}/{file}
```

- 用 `data.json`（逻辑导出）而非直接拷贝 db 文件：跨版本兼容、可合并导入、可被其他工具读取。
- 加密笔记在备份中保持**密文**（DEK 无法导出）；恢复到同设备同密钥可解。
  manifest 标注此事实，并在导出时提醒用户："换机恢复前请先解除笔记加密"。
- 自动备份轮换：目录内保留最近 5 份，命名含时间戳。

### 5.2 导入模式

| 模式 | 行为 |
|------|------|
| 覆盖 | 清空现库 → 全量导入（二次确认，红色警示） |
| 合并 | 按内容指纹（title+createdAt）去重；冲突双留；id 全部重映射 |

数据库版本升级前自动执行一次内部备份到 `filesDir/upgrade_backup/`。

## 6. WebDAV 同步设计要点（S-03, P2）

```
远端目录: /notices/
 ├─ meta.json                  // 远端清单：noteId→{etag, updatedAt, deleted}
 └─ notes/{uuid}.json          // 单笔记包（content+attachments内联Base64或分文件）
同步算法: 三向比较(本地 syncDirty / 远端 etag / 上次同步点)
冲突: 双方都改 → 远端版本另存为"xxx（冲突副本 6月10日）"，绝不静默覆盖
```
首版只做手动+定时全量比对（数据量小，简单可靠优先）。

## 7. 隐私原则

1. 默认**零网络**：除用户主动开启同步/下载 OCR 模型，App 不发任何请求。
2. 不接入统计、广告、崩溃上报 SDK；崩溃日志仅写本地，用户可手动导出。
3. 所有权限运行时按需申请，拒绝后功能降级而非阻塞。
4. manifest 配置 `android:allowBackup="false"`（防 adb 备份绕过加密），数据迁移走自建备份。
